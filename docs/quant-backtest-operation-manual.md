# 量化策略系统操作手册

本文记录量化策略实验的日常使用方式，并附一次真实回测记录。系统只做研究和回测增强，不连接券商，不自动下单，不构成投资建议。

## 启动与检查

1. 进入项目目录：

   ```bash
   cd stock-opportunity-lab
   ```

2. 安装依赖和启动本地服务。量化回测现在固定使用 `vectorbt`，请确保本机有 `python3.12`；如果 `.venv` 是 Python 3.14 或其他版本，请先删除后重新执行 setup：

   ```bash
   npm run setup
   npm run dev
   ```

3. 打开前端：

   ```text
   http://127.0.0.1:5173/backtest
   ```

4. 确认后端可用：

   ```bash
   curl http://127.0.0.1:8000/api/health
   ```

   正常响应为 `{"ok":true,"message":"ready"}`。

5. 进入页面后，在顶部“选择研究任务”中切换到 `量化策略`。它和“次日验证”是两个独立工作区，不共用结果口径。

## 一次回测怎么跑

1. 选择回测区间。
   - `开始日期`：组合回测起点。
   - `结束日期`：组合回测终点。

2. 确认回测引擎。
   - 当前系统只对外使用 `vectorbt`。
   - 后端通过 vectorbt adapter 先生成 A 股订单矩阵，再调用 `Portfolio.from_orders` 回测。
   - 如果 `vectorbt` 或 `numba` 不可用，任务会明确失败，不再降级到 internal。

3. 选择策略模板。
   - `均线趋势`：用快慢均线信号生成入场/退出。
   - `放量突破`：用涨幅、量比、成交额阈值生成信号。
   - `当前机会池复刻`：区间首日买入股票池，区间末日退出，用来粗看候选池组合表现。

4. 选择股票池。
   - `候选机会`：使用某天选股报告里的候选池。
   - `筛选通过池`：使用某天选股报告里的通过池。
   - `手动代码`：手动输入股票代码，支持逗号、空格、分号分隔。

5. 填写资金假设。
   - `最大持仓`：最多同时持有多少只。
   - `单票仓位%`：单只股票占初始资金比例。
   - `手续费率` 和 `滑点率`：位于“高级设置”，合并计入交易成本。

6. 检查运行前状态和摘要。
   - 页面会逐项检查日期、股票池、参数组合数和 vectorbt 引擎。
   - 有阻断项时会写明原因，运行按钮保持不可用。
   - 检查通过后，再核对 `回测区间`、`股票池`、`策略参数`、`参数实验` 和 `资金假设`，然后点击 `运行量化回测`。

7. 等待后台任务完成。
   - 提交后页面会显示任务进度。
   - 完成后会出现 `实验摘要`、`每日收益对比`、回撤曲线、每日交易策略、交易列表、参数组合排名和历史量化实验。
   - `每日收益对比` 会把策略累计收益和上证指数累计收益画在同一张图里，便于判断策略是否跑赢基准。
   - `每日交易策略` 会列出每天买入、卖出、收盘持仓、策略日收益和上证指数累计收益。

8. 查看落盘报告。
   - 每次回测会写入 `data/reports/quant_runs/`。
   - 常见文件包括 JSON 汇总、权益 CSV、每日策略 CSV、交易 CSV 和 Markdown 报告。
   - Markdown 报告包含 `每日收益对比`、`每日交易策略`、`买卖明细` 和 `参数排名` 四块，适合直接复盘。

## 使用体验问题与优化

本次实跑时最明显的问题是：参数分散在多个控件里，点击运行前需要来回确认日期、股票池、策略参数、仓位和成本，容易漏看一个条件。

已优化：

- 在运行按钮前新增 `运行前摘要`，集中展示本次会提交给后端的关键配置。
- 量化策略提升为回测实验室的一级研究任务，不再藏在证据页签中。
- 新增运行前检查，直接说明日期、报告、手动股票池、参数组合或引擎的阻断原因。
- 交易成本和参数网格收进高级设置，默认界面只保留日常必填项。
- 历史实验不再自动覆盖当前结果；选择历史实验时会标记上下文是否匹配。
- 摘要和真实提交参数共用同一份参数构造逻辑，避免 UI 展示和后端请求不一致。
- 摘要会随日期、股票池、策略模板和成本假设实时变化。
- 增加策略累计收益与上证指数累计收益的同图对比，不再只看最终总收益。
- 增加每日交易策略表和 Markdown 报告中的买卖明细，能看到每天买了什么、卖了什么、还持有什么。
- 量化回测已迁移为 vectorbt-first：正式路径使用 vectorbt adapter 生成订单并调用 `Portfolio.from_orders`。
- adapter 遵守 A 股 T+1：当日买入不会在同一交易日卖出。
- 成交价格只取真实当日收盘价；估值可前向填充，但缺少真实价格时只记录观察原因，不虚构成交。
- 买入数量按目标仓位向下取 100 股整数倍；不足 100 股时记录未成交原因。
- 卖出侧默认计入 `0.0005` 印花税，手续费和滑点仍由页面输入控制。
- 参数组合排名在排序后重新编号，避免报告里出现 `2, 3, 1` 这种不连续名次。

后续可以继续优化：

- 历史实验支持一键恢复整套参数到当前表单。
- 报告文件路径在 UI 内提供复制入口。
- 增加更多 vectorbt adapter 诊断，例如 T+1 阻断、价格缺失和不足 100 股的汇总筛选。
